## 0. 根因（实现线已定位，本归档补可控复现）

宿主 `@deepseek-ai/dsh-app-boot` 在加载任何 profile 之前跑插件兼容门：

```js
// D:/dsh/resources/app.asar → dsh/node_modules/@deepseek-ai/dsh-app-boot/lib/index.js
// evaluatePluginCompatibility(manifest, exemptions, runtimeVersion = getDshRuntimeVersion())
if (name !== "@deepseek-ai/dsh" && !name.startsWith("@deepseek-ai/dsh-")) continue;
const requirement = ["workspace:^","workspace:~","workspace:*"].includes(range) ? runtimeVersion : range;
if (requirement.trim() === "" || !semver.satisfies(runtimeVersion, requirement, { includePrerelease: true })) peers[name] = range;
```

`getDshRuntimeVersion()` 读的是 **app-boot 自己的 package.json version**（= dsh 运行时版本）。
2026-09-28 桌面宿主升到 `0.2.0-rc.1` 时本包 peer 只写到 `^0.1.7-rc.1` → 不满足 → **bundle 整层跳过 / 行 disabled**。

**semver 语义实测**（semver 7.8.5，与宿主同库同选项）：

```
semver version 7.8.5
OLD satisfies(0.2.0-rc.1) includePrerelease=true -> false     ← 事故判据
OLD satisfies(0.2.0-rc.1) default             -> false
NEW satisfies(0.2.0-rc.1) includePrerelease=true -> true      ← 修复后
NEW satisfies(0.1.7-rc.1, includePre=true) -> true            ← 修复不丢旧线
NEW satisfies(0.1.7-rc.2, includePre=true) -> true
NEW satisfies(0.2.0,      includePre=true) -> true            ← 未来转正也覆盖
NEW satisfies(0.2.0-rc.2, includePre=true) -> true
```

## 2. 三类失效的复现结果

### 2.1 失效一：HTTP 全 401（**成功复现，且查清判据**）

**(a) 拒装窗口（复现，端口 3098）** —— 收窄 peer 启动时宿主日志：

```
dsh web: http://127.0.0.1:3098/?token=...
[stderr] dsh: skipping profile bundle "@dsh-external/dsh-nautilus": Error: Plugin @dsh-external/dsh-nautilus@0.0.1
is incompatible with dsh 0.2.0-rc.1: peerDependencies {"@deepseek-ai/dsh-host-webserver":"^0.1.1-rc.2 ||
^0.1.2-alpha.2 || ^0.1.5-rc.1 || ^0.1.6-alpha.1 || ^0.1.7-rc.1"}. Running it may cause crashes or data loss.
Update the plugin or install a plugin version compatible with this dsh runtime. To accept this risk explicitly,
grant the exact-version exemption for @dsh-external/dsh-nautilus@0.0.1 on dsh 0.2.0-rc.1 with
`dsh plugin allow-version` or the plugin manager, then retry the installation or restart dsh.
Exact-version exemption: not active.
```

同一实例上的 HTTP 探测（**这就是守谷人 22:44–22:52 看到的形态**）：

```
B1 KNOWN exact /api/nautilus/m2/state      : ERR 401 [] :: unauthorized
B2 KNOWN exact /api/nautilus/m2/alignments : ERR 401 [] :: unauthorized
B3 unknown     /api/nautilus/nope          : ERR 401 [] :: unauthorized
B4 unknown     /api/pet/state              : ERR 401 [] :: unauthorized
```

**关键**：拒装窗口内 B1–B4 **全都是同一个 401** —— 此时未知路径的 401 与「未注册」不可区分。

**(b) 修复后（端口 3099 / 桌面 19387）**：

```
C1 KNOWN exact /api/nautilus/m2/state  : OK 200 [application/json; charset=utf-8]
                                         :: {"revision":1790608647388,...}
```

**(c) 判据甄别实验（运行中的桌面实例 19387，头矩阵）**：

| # | 请求 | 结果 |
|---|---|---|
| 1 | `GET /api/nautilus/m2/state`（无额外头） | **200** 我们的 JSON |
| 2 | `GET /api/nautilus/nope` | 401 裸文本 `unauthorized` |
| 3 | `GET /api/pet/state` | **200**（pet 可跑参照） |
| 4 | `GET /api/pet/nope` | **401 裸文本 `unauthorized`** ← pet 也不能幸免 |
| 5 | `GET /api/nautilus/m2/state` + `Sec-Fetch-Site: cross-site` | 403 + 我们门自己的 `seen` 回显 |
| 6 | `GET /api/nautilus/m2/state` + 自身 Origin + same-origin | 200 |

→ **结论**：`/api/*` 未知路径的 401 来自宿主 `/api` 承载层的兜底门，
**任何插件一样**，**不能**作为「本插件未注册」的证据。
正确判据 = **打一个本该已注册的 exact 路径**（`/api/nautilus/m2/state`）。

## 4. 新线索（对照：pet 为什么能过而我们不能）

1. **`/api/pet/nope` 同样 401** —— 这条对照直接推翻了「401 等于本插件路由没注册」。
   pet 的 `/api/pet/state` 之所以 200，只是因为它**装上了**（`@linxin666/dsh-web-all` 的 peer 覆盖了 0.2.0），
   而不是因为它走了什么特殊通道。**同一张 exact 路由表、同一道兜底门，差别只在装没装上。**
2. **`@deepseek-ai/dsh-client-connection` 不是 0.2.0 新增**（更正流传说法）：
   0.1.7-rc.2 的 CLI 闭包里就装着它——`node -e` 从 CLI 解析得到
   `C:\Users\15266\AppData\Roaming\npm\node_modules\@deepseek-ai\dsh\node_modules\@deepseek-ai\dsh-client-connection`，`version 0.1.7-rc.2`；
   且 `dsh --profile al7probe17 --dump-config` 在 0.1.7 组合里输出 `connection: '@deepseek-ai/dsh-client-connection'`。
   两版探针上「未知 /api 路径 → 401 裸文本 `unauthorized`」实测同形 ⇒ 本次事故与它无关。
3. **桌面壳为什么不需要迁到连接层**（代码级旁证）：Electron `main.js` 的 `forwardWebRequest`
   （`app.asar → lib/main.js` 约 7182 行）转发 `/api` 时会
   **删掉 `host`/`origin`/`cookie`/`sec-fetch-site`**，再 `headers.set("cookie", hostCookie)`；
   于是插件同源门看到的是「无跨站信号」（site=undefined、origin=undefined）→ 走 `noCrossSiteSignal` 放行。
   桌面端面板因此本来就该是通的，前提只是**插件被装上**。
4. **`forwardWebRequest` 只对 `dsh-app://app` 的 `origin` 放行**（`origin !== "dsh-app://app"` → 403），
   `dsh-app` 在 `registerSchemesAsPrivileged` 里声明为 `standard/secure/supportFetchAPI/corsEnabled`。
5. **asar 的 `size` 字段本机实测短报 2 字节**（末两字节 `\n}` 缺失，直接 `JSON.parse` 会抛
   「Expected ',' or '}' after property value」）。按偏移读 asar 时要多读余量并按首 `{` / 末 `}` 收紧——
   `test-host-compat.mjs` 的 `versionFromAsar` 已按此实现（技法沿用任务书给的「读头部 → 偏移」路线）。
