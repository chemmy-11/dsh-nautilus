# 对齐 rubric 的 Correction 记录（AL.5 · 只添不改）

> 机制照抄雪谷 vault `门/correction.md`：错误不是被抹掉的，是被接住、被记录、变成下一版 rubric 的基底。
> 闭环：**发现 → 记录 → 修复 → 回归**。
>
> 规则：
> 1. **只添不改**——修正与回归以「后记」追加，不覆盖原始刻痕。
> 2. 每条含四项：**情境**（什么时候）· **错**（对齐/边界判错在哪）· **根**（为什么是错，不是风格差异）· **修**（rubric 下一版怎么写）。
> 3. **升级条款**——同类错误反复出现，升入决策文档 §2 的锚文（改锚即 `rubric_version` 递增，新旧不混算）。
> 4. **状态**：记录 / 待回归 / 已回归（注明验证场景与留出集前后数字）。
> 5. **留出集不可污染**：用于采纳判定的样本绝不进提示词、不进例库（决策 §5）。

## 触发方式

1. `node scripts/alignment-consistency.mjs`（只读）看三指标与留出集；
2. `npm test` 全绿后，取 `|自评 − 人工|` 最大的样本集做人工复核；
3. 按下面模板写一条；同类第二次出现即触发升级条款。

## 记录模板（复制后追加，勿改旧条）

```
## YYYY-MM-DD · 一句话标题
- **情境**：哪一批样本 / 哪一档 / 什么场景
- **错**：实测数字（人工 X 条中 Y 条判成 Z）+ 具体例子（可回查 key）
- **根**：为什么是错——是锚文歧义、边界枚举缺项，还是代际混算
- **修**：rubric_version+1 的具体改法（锚文一句话 / 例库加哪条）
- **留出集回归**：改动前 κ=… / 完全一致 …% → 改动后 κ=… / …%（**提升才采纳，否则回滚**）
- **状态**：记录 / 待回归 / 已回归（验证场景）
```
