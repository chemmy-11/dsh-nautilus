## 0. 问题

pulse 采集层已经把 OS/GPU 读数按 5s 原始节奏落了库（14 天保留），但**没有任何一条线会主动说话**：
读数只有人打开工作台才被看见，越线现场（CPU/内存/显存/GPU 拉满的那一刻）事后既无证据也无结论。

## 1. 定位与红线

- **只做四件事**：越线 → 报警（工作台图标闪红）→ 冻结原始证据 → 成文（LLM 报告）→ 沉淀台账。
- **不自动处置**：不杀进程、不改宿主配置、不动用户数据。报警是**提示 + 留证 + 成文**，处置永远由人做。
- 不写 vault（红线 2）：报告与台账落在 `~/.dsh/nautilus/alerts/`；要沉笔记走会话侧 /obsidian 人工触发（OQ-A3）。

## 2. 关键澄清：不是新增录制，而是「抽取 + 冻结 + 哈希」

`metric_sample` 已是 5s 原始采样、保留 14 天——**越线前 2h（D-A8 起 4h）的数据在报警那一刻已经在库里**。
所以 A.2 要做的不是再录一份，而是从既有长表里按原生节奏抽出窗口切片、算出覆盖率与指纹、写进独立目录，
并给它**独立的保留期**（不受 14 天原始保留影响）。

## 5. 判定口径（A.1 实现，逐条来自实测教训）

1. **确认窗是时间窗（`forMs`），不是 tick 数**：三族量化实测 1×/2×/3×（本地族 5s / 计数器族 15s / GPU 族 10s），
   用 tick 数会让同一条规则换个对象就换了语义。
2. **滞回**：越线看 `threshold`、解除看 `clear`；两线之间保持现状（已确认的继续挂着，未确认的不起算）。
3. **连续段被打断即重置计时**：E26 边界实证（19:54:21 越线 → 19:54:27 回落 0.89926 → 连续段自 19:54:32 重算），
   抖动不产生告警。
4. **缺样本 ≠ 恢复**：指标缺席（或 ratio 分母为 0）时跳过本 tick 且**状态保持**。
5. **停用不擅自解除**：规则被关掉或被删掉，内核不解除已确认的告警；遗留未解除行由**启动自愈**收口
   （重启后连续段与峰值都不可考，不装「还活着」）。
6. **冷却**：解除后 `cooldownMs` 内不开新告警，但**计时继续累积**——冷却一过，仍在越线态且连续段够长的规则立刻确认。
7. **峰值**：越线段内取极值（gte 取 max、lte 取 min），落台账 `peak_value`。
8. **无原文/无值不判断**：比不出数的规则一律跳过，宁可漏报也不臆造。

## 7. 诚实边界（随读数一起引用）

1. 回测只覆盖**本机这段历史**（14 天保留期，过期只能重采），换机器必须重跑——默认值是「本机起点」，不是普适红线。
2. 冻结的是**原始采样**，不是「越线那一刻的完整现场」：采样周期内的尖峰可能被平滑掉，覆盖率的空洞要如实标注。
3. **告警自身的噪声地板由 `human_verdict` 量化**（真阳性/假阳性/未知三分），未裁决的告警不得计入阳性率。
4. LLM 输出只作**候选假设**（`api` 时代只作对照，不作归因）；事实段由程序生成，模型只填假设段。
5. 手动采样档（心跳 = manual）下没有连续监测——**此时的静默不是「没越线」，是没在看**（已在 UI/文档明示）。
